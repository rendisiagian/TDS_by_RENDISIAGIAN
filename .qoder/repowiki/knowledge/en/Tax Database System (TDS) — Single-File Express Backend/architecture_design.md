Monolithic single-file application (`app.js`, ~3060 lines) bootstrapped by `package.json` with `node app.js`. It wires together: Express 5 for HTTP, `express-session` + bcryptjs for cookie-based auth with role checks (`administrator`/`supervisor`/`superadmin`), `socket.io` over the same HTTP server for real-time bulk-upload progress, `sqlite3` for an on-disk `tax_database.db`, `helmet` for generic headers, and `express-rate-limit` on `/login`. The DB is initialized in a `db.serialize()` block that creates all tables (`users`, `audit_logs`, `master_cabang`, `master_vendor`, `master_client`, `data_vatin`, `data_vatout`, `item_*`, `inbox_*`, `data_prepaid`, `data_payable`, `projects`, `porsi_vatout`, `data_client_ledger`) and runs one-shot migrations. Four business modules are declared as a data-driven array (`vatin`, `vatout`, `payable`, `prepaid`) so table names, inbox tables, item tables, and static archive folders (`arsip_vatin`, `arsip_vatout`, `arsip_payable`, `arsip_prepaid`) are generated from it. Each module folder under the root holds its own HTML dashboard plus an `arsip_*` subfolder of PDFs served via `express.static`. Client-side pages live at the repo root (`dashboard_utama.html`, `sidebar.html`, `login.html`, `profile.html`, `manage_users.html`, `master_cabang.html`, `master_kontak.html`, `audit_logs.html`, `taxprojectreport.html`, `accounting/client_ledger.html`) and call REST endpoints under `/api/*`; shared UI helpers live in `pagination.js`, `sidebar.js`, `theme.js`, `toast.js`, `utils.js`. A separate `export.js` script handles offline report generation. Socket.IO shares the session store so upload progress is tied to the authenticated user.
