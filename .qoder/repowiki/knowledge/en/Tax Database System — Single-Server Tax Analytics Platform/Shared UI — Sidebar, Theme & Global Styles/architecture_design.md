Three independent, globally-scoped files that are loaded on every page:
- `sidebar.js` is wrapped in an IIFE and uses a `MutationObserver` on `document.body` to react when the asynchronously fetched sidebar DOM appears. It synchronizes the entity dropdown with `localStorage('lastEntitas')`, fetches available years from `/api/years-vatout?entitas=...`, injects `<a>` links into `#sub-vatout`, and exposes `window.refreshSidebarYears` for re-invocation.
- `theme.js` is also an IIFE that sets `data-theme` on `<html>` from `localStorage('theme')`, exposes `window.__toggleDarkMode` and `window.toggleSidebarGroup` / `window.toggleSubMenu` as global handlers, and polls for the active sidebar link via a 100 ms interval (capped at 4 s) to expand the correct `.sidebar-group` and `.sidebar-item-nested`.
- `style.css` defines the complete design system: CSS custom properties under `:root` for light/dark palettes, semantic color tokens (`--primary-*`, `--gray-*`, `--success-*`, etc.), spacing/transition/radius variables, and component styles for sidebar, header, cards, tables, badges, buttons, forms, modals, login, and scanner screens. Dark mode is toggled purely by the `[data-theme="dark"]` attribute selector.

Dependency direction is one-way: both JS files read/write `localStorage`, call server endpoints via `fetch`, and mutate DOM classes; neither imports the other. The CSS is the single source of truth for visual appearance and is consumed by HTML templates through class names like `.sidebar-group`, `.sidebar-item-nested`, `.sidebar-link.active`, `.dark-mode-toggle`, etc.
