Three standalone client-side HTML pages share a common UI framework loaded from global paths (`/theme.js`, `/toast.js`, `/pagination.js`, `/export.js`, `/sidebar.js`, `/utils.js`, `/style.css`) and communicate with the backend via REST (`fetch('/api/data-prepaid')`, `/api/inbox-prepaid`, `/api/summary-prepaid`, `/api/prepaid-comparison/:noBppu`, `/api/available-vatout`, `/api/branches`, `/api/me`) plus Socket.IO events (`data-baru-prepaid`, `update-tabel-prepaid`, `simpan-final-sukses`, `upload-batch-selesai`, `request-action-faktur`, `hapus-inbox-prepaid`). The `dashboard_prepaid.html` page renders the main register table with server-side pagination, per-column filtering, MoM stats, and a maker-checker edit/delete flow. The `inbox_prepaid.html` page handles batch PDF upload (client-side text extraction via pdf.js), displays pending documents, and provides a review modal to fill branch and link one or more VAT OUT invoices before final submission. The `summary_prepaid.html` page aggregates BPPU vs VAT OUT data by tax period. All three pages support multi-entity switching through a `lastEntitas` localStorage key and a shared sidebar. The `arsip_prepaid/` directory is a static archive of ~150 locally stored PDFs named `PRE_<id>.pdf` referenced by the dashboard's PDF column.
