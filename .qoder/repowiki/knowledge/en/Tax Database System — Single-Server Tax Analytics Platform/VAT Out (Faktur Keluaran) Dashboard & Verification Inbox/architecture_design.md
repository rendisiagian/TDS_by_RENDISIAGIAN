Three standalone HTML pages share the same shared frontend assets loaded from `/` (`theme.js`, `toast.js`, `utils.js`, `sidebar.js`, `export.js`, `pagination.js`, `style.css`) plus Socket.IO for real-time updates. `dashboard_vatout.html` is the main register view: it paginates and filters rows via `GET /api/data-vatout`, shows stats cards with month-over-month comparison, and supports Edit/Delete actions routed through `socket.emit('request-action-faktur', ...)` to a supervisor approval flow. `inbox_vatout.html` is the verification queue: users upload multiple PDFs which are parsed client-side with pdf.js into text + buffer payloads sent via `socket.emit('upload-pdf-vatout-batch')`; each row can be opened in a modal to manually fill internal fields (branch, VO, invoice number) before calling `socket.emit('simpan-final-vatout')`. `summary_vatout.html` consumes `GET /api/summary-vatout` to render Chart.js line and doughnut charts plus a monthly recap table. All three pages fetch user info from `GET /api/me` and branch/VO metadata from `GET /api/branches?entitas=` and `GET /api/vo/{branch}`. The `arsip_vatout/` directory holds the actual archived PDF invoices organized under subfolders named by entity/code prefixes.
