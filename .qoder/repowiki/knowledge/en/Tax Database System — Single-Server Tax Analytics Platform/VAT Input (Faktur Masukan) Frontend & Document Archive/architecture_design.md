Three standalone HTML pages serve as the UI layer: `dashboard_vatin.html` is the primary register with server-side pagination, filtering, PDF upload via pdf.js, and Socket.IO real-time updates; `audit_vatin.html` displays three anomaly tables (orphan replacements, replaced normals, different tax periods) fetched from `/api/audit-vatin`; `summary_vatin.html` renders period-over-period PPN vs. invoice-date comparison using Chart.js against `/api/summary`. All pages share common shell assets loaded from `/` (`theme.js`, `toast.js`, `export.js`, `sidebar.js`, `utils.js`, `style.css`) and fetch a shared sidebar via `/sidebar.html`. Data flows through REST endpoints (`/api/data-vatin`, `/api/items/vatin/:no_faktur`, `/api/branches`, `/api/me`) plus Socket.IO events (`upload-pdf-vatin-batch`, `request-action-faktur`, `data-baru-vatin`, `upload-batch-selesai`). The `arsip_vatin/` subdirectory is a flat document store containing thousands of vendor PDFs named with patterns like `{batchPrefix}_{NPWP}_{Company}.pdf`, grouped by batch prefixes (`20305G_`, `250310_`, `30236G_`, `Berca JO_`, `Perlu Verifikasi_`). There is no backend code in this scope — it is purely the client-facing slice that consumes the server's API.
