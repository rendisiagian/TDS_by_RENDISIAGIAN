Three independent, globally-scoped files loaded on every page with no inter-file imports:
- `sidebar.js` (IIFE) uses a `MutationObserver` on `document.body` to react when asynchronously injected sidebar DOM appears; it syncs `#global-entity-select` with `localStorage('lastEntitas')`, fetches available years from `/api/years-vatout?entitas=...`, injects `<a>` links into `#sub-vatout`, and exposes `window.refreshSidebarYears` for re-invocation.
- `theme.js` (IIFE) sets `data-theme` on `<html>` from `localStorage('theme')`, exposes `window.__toggleDarkMode`, `window.toggleSidebarGroup`, and `window.toggleSubMenu` as global handlers, polls for the active sidebar link via a 100 ms interval (capped at 4 s) to expand the correct `.sidebar-group` / `.sidebar-item-nested`, and loads user info from `/api/me`.
- `style.css` is the single source of truth for visual appearance: CSS custom properties under `:root` define light/dark palettes, semantic tokens (`--primary-*`, `--gray-*`, `--success-*`, etc.), spacing/transition/radius variables, and component styles for sidebar, header, cards, tables, badges, buttons, forms, modals, login, and scanner screens. Dark mode toggles purely through `[data-theme="dark"]` attribute selectors.
Dependency direction is one-way: both JS files read/write `localStorage`, call server endpoints via `fetch`, and mutate DOM classes; neither imports the other. The CSS is consumed by HTML templates through class names like `.sidebar-group`, `.sidebar-item-nested`, `.sidebar-link.active`, `.dark-mode-toggle`, etc.
