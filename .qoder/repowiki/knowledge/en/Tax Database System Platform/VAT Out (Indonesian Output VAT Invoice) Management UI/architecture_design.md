Three standalone static HTML pages (`dashboard_vatout.html`, `inbox_vatout.html`, `summary_vatout.html`) share common frontend assets loaded from the project root (`/theme.js`, `/toast.js`, `/utils.js`, `/sidebar.js`, `/export.js`, `/pagination.js`, `/style.css`). Each page bootstraps by loading `/sidebar.html` into `#sidebar-container`, then calling `GET /api/me` to populate the header user name. The dashboard renders a paginated, filterable register table via `GET /api/data-vatout`, shows month-over-month stats cards, and drives Edit/Delete actions through `socket.emit('request-action-faktur', ...)` routed to a supervisor approval flow. The inbox page is the verification queue: users select multiple PDFs that are parsed client-side with pdf.js 2.16.105 into text + buffer payloads sent via `socket.emit('upload-pdf-vatout-batch')`; each row opens a modal where internal fields (branch, VO, invoice number) are filled before calling `socket.emit('simpan-final-vatout')`. The summary page consumes `GET /api/summary-vatout?entitas=` to render Chart.js line and doughnut charts plus a monthly recap table. All three pages fetch branch metadata from `GET /api/branches?entitas=` and optional VO lists from `GET /api/vo/{branch}`. Archived PDFs are stored as plain files under `vat_out/arsip_vatout/` organized by entity/code prefixes.
