- Each page initializes its active entity from `localStorage.getItem('lastEntitas')` and exposes a global `window.gantiEntitas(entitas)` function that updates the sidebar select and reloads the view.
- Server communication follows a consistent pattern: REST endpoints return JSON with `{ data, total, stats }` shapes, while state changes are propagated via Socket.IO events listened on both the dashboard and inbox pages.
- Per-column filtering is implemented by attaching `.filter-input` (or `.filter-input-inbox`) inputs in a filter row, debouncing input at 500ms, and serializing non-empty filters into a `search` query parameter as a JSON string.
- VAT OUT invoice selection uses a duplicated UI across dashboard and inbox: a search input, an auto-populated dropdown from `/api/available-vatout`, a toggle to manual input mode, and selected items persisted as a comma-separated hidden field.
- Maker-checker authorization checks `currentUser.role` against `['supervisor', 'administrator']` before allowing direct API calls; non-supervisors submit actions via `socket.emit('request-action-faktur', ...)` instead of calling APIs directly.
- Branch selection is locked to a fixed value (`Berca JO`) when `aktifEntitas === 'JO'`, otherwise populated dynamically from `/api/branches?entitas=...`.
