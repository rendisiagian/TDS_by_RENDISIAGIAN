Three standalone static HTML pages — `dashboard_prepaid.html` (register table), `inbox_prepaid.html` (verification queue with batch PDF upload and review modal), and `summary_prepaid.html` (BPPU vs VAT OUT comparison) — share a common UI framework loaded from global paths (`/theme.js`, `/toast.js`, `/pagination.js`, `/export.js`, `/sidebar.js`, `/utils.js`, `/style.css`) and communicate with the parent Node.js backend via REST endpoints (`/api/data-prepaid`, `/api/inbox-prepaid`, `/api/summary-prepaid`, `/api/prepaid-comparison/:noBppu`, `/api/available-vatout`, `/api/branches`, `/api/me`) plus Socket.IO events (`data-baru-prepaid`, `update-tabel-prepaid`, `simpan-final-sukses`, `upload-batch-selesai`, `request-action-faktur`, `hapus-inbox-prepaid`). The dashboard renders server-side paginated data with per-column filtering, MoM stats, and maker-checker edit/delete flows; the inbox uses pdf.js (CDN 2.16.105) to extract text from uploaded PDFs client-side before submitting them; the summary page aggregates BPPU and VAT OUT totals per tax period. A shared sidebar is injected via `fetch('/sidebar.html')` and entity switching is coordinated through a `lastEntitas` localStorage key and a global `window.gantiEntitas(entitas)` function exposed by each page. The `arsip_prepaid/` directory holds ~150 locally archived PDFs named `PRE_<id>.pdf` referenced by the dashboard's `link_pdf_lokal` column.
