Two standalone static HTML pages (`dashboard_payable.html`, `inbox_payable.html`) share a common client-side architecture built on top of shared scripts loaded from the app root (`/theme.js`, `/toast.js`, `/pagination.js`, `/utils.js`, `/sidebar.js`) and Socket.IO for real-time communication. The dashboard page renders paginated BPPU records via server-side filtering at `/api/data-payable` with aggregate stats (total docs, PPh, DPP, pending count), debounced inline search, and Edit/Delete actions gated by a Maker-Checker role model (supervisor/administrator act directly; others submit requests via `request-action-faktur`). The inbox page handles batch PDF upload using pdf.js 2.16.105 to extract text client-side, emits chunks via `upload-pdf-payable-batch`, listens for `upload-batch-selesai` progress events, and provides a verification modal that cross-references VAT IN invoices (`/api/data-vatin`) by NPWP/name matching before final submission through `simpan-final-payable`. Both pages fetch the sidebar dynamically from `/sidebar.html`, resolve the current user from `/api/me`, persist the active entity (`lastEntitas`) in localStorage, and communicate with the backend via both REST (`fetch`) and Socket.IO events (`data-baru-payable`, `update-tabel-payable`, `hapus-inbox-payable`).
